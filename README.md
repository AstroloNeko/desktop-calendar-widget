# 桌面月历 Desktop Calendar

一个轻量的 Windows 桌面月历挂件：像经典 Win7 Gadget 一样停留在桌面层，不遮挡普通应用，同时提供 DDL、颜色分类、事项类型和提前提醒。

当前版本：**v0.12.0**。Calendar Agent 支持备忘录式快速创建、结构化多事项操作和多轮确认。全局视图右侧可直接使用 AI 助理；新装默认 SQLite，已有 JSON 日历保留自主升级选择。可在“更多 → 数据管理”查看存储类型。

## 下载和使用

1. 在 [Releases](https://github.com/AstroloNeko/desktop-calendar-widget/releases) 下载 `DesktopCalendar-win64.zip`。
2. 解压到任意可写目录。
3. 双击 `DesktopCalendar.exe`。

软件默认位于普通应用窗口后面；按 `Win+D` 可以快速回到桌面查看。单击月历会临时进入普通前台，切换到其他应用后自动回到桌面层；只有需要持续覆盖其他窗口时，才需要点击顶部状态切换为“置顶”。

点击右上角横线或按 `Alt+F4` 只会把月历隐藏到系统通知区域，日程提醒和习惯清单仍会继续运行；需要完全退出时，请右键托盘图标选择“退出桌面月历”。

不要只把 EXE 单独移出解压目录；程序旁边的 `_internal`、`DesktopCalendarUpdater.exe` 和 `DesktopCalendarRepair.exe` 都应保留。

## 功能

- 372 像素宽的无边框桌面挂件，可拖动并记忆位置
- Global 无边框大窗口：月度排期与任务时间轴共享数据，支持任务栏最小化/恢复和返回紧凑视图
- 两种 Global 视图支持移动事项、拖动端点调整日期，预览不写入数据，释放后一次保存，Esc 取消
- 事项操作支持 Ctrl+Z / Ctrl+Y 撤销重做；默认 100 步会话历史，文本输入优先保留自身撤销
- Ctrl+K 搜索历史/未来事项的标题、备注、分类，并执行日期跳转和常用命令
- 桌面模式与临时置顶模式
- 桌面模式支持点击临时前台、失去交互后智能归位
- 月历色点、当天日程、逾期状态和完成状态
- 习惯清单：按天、周、月、年及间隔周期打卡，每次完成记录独立；待办完成一次后结束
- 习惯清单可独立设置提醒时间，并按周期及“仅工作日”选项执行；启用该选项时跳过假期和请假日，调休工作日照常执行
- 单击日期查看，双击日期打开当天完整事项详情，右键打开快捷菜单
- 快速输入支持选择颜色和一般/紧急/DDL 三种事项类型，按 Enter 保存
- 颜色分类、事项类型、备注和多种提前提醒
- 日程时间可留空；无具体时间的事项按当天结束计算截止时间，开启原生提醒后按配置的提醒时刻执行
- 日程可设置持续 1～365 天，只保存一次并在覆盖的每一天显示
- 跨日事项可按有效工作日展开，自动跳过周末、法定假期及手动请假/放假日
- 日期可手动标记为正常、请假或放假，并在重启后保留
- DDL 事项提供日期提示、临近截止汇总和 24 小时内强制置顶区域
- Windows 原生日程通知支持点击打开事项与稍后 10 / 30 / 60 分钟；习惯提醒沿用原有设置
- 未来 7 天和逾期事项汇总
- 系统通知区域常驻图标，支持恢复月历、打开全局视图、隐藏到托盘和彻底退出
- “后台与提醒”统一设置与只读“提醒计划”概览，支持单事项规则、隐私模式及测试通知
- 中国大陆 2026 年法定节假日/调休，以及 2024—2030 年常用公历与农历节日
- 日程区展开/收起、透明度调整和多显示器边界保护
- 可选开机启动、完整数据备份/安全恢复和单实例保护
- 从 GitHub Releases 检查、校验、下载并自动安装更新

数据目录为 `%APPDATA%\DesktopCalendar`。全新用户直接使用 SQLite；已有 JSON 日历继续使用 `calendar_data.json`，直到主动升级。SQLite 由 `storage-state.json` 指定唯一权威数据库 `calendar-<标识>.sqlite3`。请勿自行修改状态文件或用旧 JSON 覆盖 SQLite。

### SQLite 升级与数据恢复

JSON 模式下点击主界面“升级到 SQLite”，或进入“更多 → 数据管理 → 升级到 SQLite”。应用会先停止旧运行时，再请你确认；不会静默迁移。选择“继续使用 JSON，不再提醒”会在本机保留该偏好，恢复旧备份也不会重置；关闭提示条只影响本次运行。原 JSON 与 `original-<标识>.json` 保护副本保留，激活后不再采纳旧 EXE 对旧 JSON 的修改。**不要直接用旧 EXE 回退。**

“更多 → 数据管理 → 导入旧 JSON”支持显式导入 Schema 8/9。JSON 模式下经确认后保护并替换日历；空 SQLite 下验证并转换后仍使用 SQLite；非空 SQLite 不提供直接覆盖或合并，可使用“恢复数据”对有效备份进行明确的替换恢复。导入不修改源文件。

“更多 → 数据管理”可导出和恢复备份：JSON 沿用 Format 1，SQLite 使用官方 Backup API 生成 Format 2，一并保留事项、分类、习惯历史、设置与提醒账本。支持旧备份转换恢复；恢复会清空撤销历史并失效旧 AI 待执行操作。旧备份可能遗忘近期已投递提醒，恢复前会提示可能再次提醒。

常规自动备份位于数据目录的 `backups` 文件夹。数据库损坏而无法启动时，可运行 `DesktopCalendar.exe --recover-storage` 选择有效备份；恢复前保留损坏数据库与 WAL/SHM 原件，不自动回退旧 JSON。独立 `DesktopCalendarRepair.exe` 用于修复程序文件，不等同于恢复日历数据。

### Calendar Agent · AI 私人助理

从全局视图右栏的“AI 助理”进入，或按 `Ctrl+Alt+J` 打开独立窗口；Compact 或 Global 的“更多 → AI 私人助理…”仍可使用。在设置中填写自己的 DeepSeek 兼容 HTTPS 接口、模型和 API Key，并主动同意发送必要对话/日历上下文；默认不会自动调用模型。API 费用与可用性取决于所用服务。

支持自然语言查询安排、新建和修改事项、完成事项，以及创建和持续修改 Habit 2.0 周期习惯；可以连续对话调整同一对象。明确且合法的低风险操作可直接保存，目标有歧义时先澄清，删除等高风险操作需确认。支持受控批量事项操作，实际能力以预览和本地校验为准；不要把模型回复当作保存成功的唯一依据。

AI 通过现有业务服务写入，沿用 Undo/Redo。可选启用带 Token 认证的本机 HTTP API，不是公网服务，也不包含 QQ/AstrBot 接入。凭据由当前 Windows 用户的 DPAPI 保护；`ai-assistant` 中的外部配置、聊天记录与操作日志不包含在日历备份内，也不是可跨机器直接搬用的凭据备份。

「AI 助理设置 → 微信远控」默认关闭。可以用激活码绑定，也可以填写自己的 HTTPS 服务根地址和 Worker Token。测试连接只检查公共健康接口，Worker 鉴权结果会在远程服务开始连接后显示。每台日历只启用一个执行端。微信相对日期以发送时间为准，确认和候选按发送者隔离。

远控在服务器确认绑定账号后才会领取任务或上传回执。手动接入首次核验成功后会保存账号；同一服务器更换手动 Token 时仍核验原账号，要切换账号请使用激活码重新绑定，或先清除旧绑定。缺少账号核验记录的旧待处理任务和回执保留在本机台账中，需人工核对。

从「更多 → AI 助理设置」可直接打开微信远控。远程模型和本机 API 同在「AI 设置」选项卡。微信远控页显示当前连接、绑定状态与最近 20 条本机处理记录。若绑定失效，在微信公众号发送「重新获取激活码」，再点击「重新绑定」。使用说明和连接参数可以展开查看。

Windows 通知区域中的日历图标会显示微信远控角标。绿点表示实时在线，黄点表示正在连接、重连或使用备用轮询，红点表示服务器、绑定或 AI 助理需要检查，灰点表示远程服务已关闭或未绑定。将鼠标悬停在图标上可查看具体状态。

选择「自动绑定」后，填写服务器根地址和一次性客户端激活码，点击「绑定」。成功后客户端加密保存账号与 Worker Token，再勾选「启用私人远程服务」并保存。若激活成功但本机保存失败，点击「重试本地保存」可保存已收到的凭据。

「清除绑定信息」会清除本机保存的服务器地址、账号和 Worker Token，并停止接单。「清除 AI 助理设置」会重置模型和本机 API、清除模型密钥与授权、暂停接单，并保留远程绑定。两项操作均保留日历、会话和回执台账。

启用远程服务时，Worker 会先领取积压消息，再等待 Firebase 实时通知。每次通知或重连后会排空队列。在线兜底检查默认关闭，可选 10、30 或 60 分钟。点击「手动检查」会用已保存的远程配置唤醒 Worker。连接持续不可用时自动退回 15 秒轮询。手动 Token 和自动绑定均可使用实时通知。源代码运行需安装 `requirements-remote.txt`，缺少 `requests` 时自动使用备用轮询。 [Firebase SSE 事件说明](https://firebase.google.com/docs/database/rest/retrieve-data#section-rest-streaming)

若领取超时，请按显示的 UTC 时间检查云端 `processing`。若执行结果待核查，先核对日历及云端任务状态。客户端将原回执和处理状态保存在本机加密台账 `ai-assistant/wechat-jobs.sqlite3`。服务端接受回执和微信通知送达分别记录。

### 后台运行与原生提醒

在“更多 → 后台与提醒”主动开启原生日程提醒（默认关闭），设置本地提醒时间、一般/紧急事项与 DDL 的提前天数；有具体时间的事项沿用编辑器的提醒提前量，选择“不提醒”时保持关闭。单事项规则可以另行关闭或自定义，习惯仍在“习惯清单”内独立设置提醒。

“更多 → 提醒计划”可查看需要处理、稍后提醒和即将提醒的事项，阅读完整详情、打开原编辑器或取消稍后提醒。设置页的测试通知不包含真实事项，也不会自动开启日程提醒。Windows 接受发送不等于用户已经看到；横幅及通知中心受系统权限、勿扰等策略影响。

隐藏到系统托盘后应用继续运行；双击托盘图标恢复原视图，右键可直接打开全局视图或彻底退出。Global 横线仍最小化到任务栏。彻底退出或电脑关机后不提醒；本版不新增安装器或开机启动配置。

### 快捷键设置

程序运行期间，默认按 `Ctrl+Alt+D` 打开全局视图，按 `Ctrl+Alt+J` 唤起 AI 私人助理。即使月历隐藏到托盘或最小化也可唤起；AI 助理会保留当前紧凑／全局视图。编辑器或数据操作正在进行时，优先显示当前弹窗，以免打断操作。完全退出月历后两条快捷键都不响应。

在“更多 → 快捷键设置…”可统一修改系统全局热键和月历内的搜索、新建、撤销／重做、日期导航及编辑器保存。留空保存可停用，月历内一个命令也可用英文逗号填写多个组合。保存后生效并在重启后保留；发现重复组合或全局键被其他程序占用时，保留原设置。也可点击“恢复默认”后保存。

### 源码测试与正式版的数据隔离

源码版与 EXE 默认使用同一个用户数据目录。较新的源码可能先升级数据 Schema；之后不能再用旧 EXE 打开该目录，也不能手工改低 `version`。请用支持该 Schema 的新版程序；无法更新主程序时使用新版独立修复工具，不要恢复或清空日历来消除版本错误。

开发测试请先退出正式版，再在独立 PowerShell 进程中使用隔离 APPDATA（`build` 已被 Git 忽略）：

```powershell
$calendarOriginalAppData = $env:APPDATA
try {
    $env:APPDATA = Join-Path $PWD 'build\dev-profile'
    py -3 .\app.py
} finally {
    $env:APPDATA = $calendarOriginalAppData
}
```

该命令不会搬移或复制正式数据；测试数据、日志和备份都在隔离目录。当前仍有全局单实例保护，不应通过绕开该保护让新旧版本竞争真实数据。更新交接前必须先成功保存；保存失败会中止交接，不会继续覆盖安装。正常更新使用校验后 ZIP 内的新更新器，不再使用安装目录中可能过旧的更新器。

### Global 多选与批量操作

月度排期与任务时间轴中，按住 Ctrl 单击事项可增减选择；同一个多日事项的不同片段只计一项。普通单击或拖动只处理当前事项，不移动整批选择。任务时间轴还支持 Shift 按当前事项顺序范围选择（Ctrl+Shift 为追加范围）。
选中两项以上时出现批量工具栏，可统一完成/取消完成、分类、平移日期或删除。分类保留每条事项的单独颜色覆盖；转为无分类时冻结继承的有效颜色。日期按自然日平移保存的开始日期，持续天数及跳过非工作日规则不变，实际末日 DDL 依原算法重新计算。

批量删除需两次确认；每批操作只保存一次，并可一次 Ctrl+Z 撤销、Ctrl+Y 重做。Esc 优先取消弹窗或拖拽，其后清空选择。切换月份、分类筛选、Global 视图或返回紧凑视图会清空选择，避免操作隐藏事项；Flow 的“更多”中未展示卡片不纳入多选。
多选和历史仅保留在当前会话，恢复备份时清空；不写入备份格式，不修改习惯打卡记录。工具栏不支持批量拖动，也不支持批量操作习惯。

### 习惯周期

沿用“习惯 → 习惯清单”入口，在原编辑器选择每天、每隔 N 天、每周（可多选星期）、每月、每年或自定义间隔；可设置开始日期及结束日期，默认永不结束。
新建习惯默认每天，含周末；旧习惯保留每日工作日执行及所有历史打卡记录。勾选“仅工作日”时复用现有法定调休、节假日与个人请假判断，跳过的计划不顺延。

间隔以开始日期为固定锚点：周以开始日期所在的周一作为周期周起点；月/年以开始月/年计算间隔。漏打卡不会改变未来日期。月末 29/30/31 日在不存在该日的月份跳过；每年 2 月 29 日在非闰年跳过，不漂移到月底或 3 月。
例如每隔两周的周一、三、五，开始于周三时，首周只出现周三、周五，下一执行周为两周后的周一、三、五。

仅计划日期允许新增打卡；非计划日不计入计划完成率的分母。编辑周期不删除旧记录，可在编辑器的只读“历史打卡”区域查看；历史计划本身不保留规则版本，区间统计按当前规则计算。
习惯不转换成普通事项，也不生成 Timeline 任务条；Compact 和 Global 单日详情沿用统一习惯清单。习惯操作仍不进入普通事项的撤销历史。

习惯周期和历史打卡包含在日历备份中。当前兼容旧 Schema 8 与 Schema 9 的 Format 1 备份，SQLite 模式使用独立的 SQLite Schema 1 / Format 2；不要改低版本字段来让旧程序强行读取。

### 备份与恢复

在右上角“更多 → 数据管理”中选择“备份数据…”可导出 `.dcalbackup` 文件。
它保存全部事项（含 DDL、多日排期、分类及颜色）、习惯记录、提醒历史、假期与设置；不包含程序、更新下载包、日志或缓存。
备份为带格式版本、应用版本、创建时间及 SHA256 校验的 ZIP 容器，不加密，请妥善保存个人安排。

“恢复数据…”会先检查备份，再显示来源信息并请求确认。恢复前必须先成功保护当前数据；恢复失败会回滚原数据，成功后清空当前会话撤销历史，避免旧命令修改恢复结果。
恢复替换的是全部数据，不是合并导入。事项、主题和偏好立即重载，窗口位置按现有安全边界规则恢复；保留当前 Compact / Global 工作模式。

JSON 模式沿用原自动备份及最近 10 份有效自动备份策略。SQLite 每日首次启动生成 Format 2 备份，并在恢复、更新前保护当前数据；常规备份位于 `%APPDATA%\DesktopCalendar\backups`。SQLite 备份与原件保护副本目前保守保留、不自动轮转，请注意磁盘空间。
只清理这个受控目录内已验证的自动备份，不清理手动导出、未知或损坏的文件。每日备份失败不打断使用，可在数据管理菜单查看提示；恢复和更新前的保护备份失败会中止操作。
旧 Format 1 JSON 数据限制为 32 MB，Format 2 数据库成员限制为 64 MiB。SHA256 用于发现损坏，不是来源签名；只恢复可信来源的备份。

法定放假与调休按年度公布，当前内置 2026 年国务院办公厅安排；常用节日可在右上角菜单中关闭显示。

## 自动更新

打开右上角 `···` 菜单，点击“检查更新”。如果 GitHub Releases 存在更高版本，软件会：

1. 下载 `DesktopCalendar-win64.zip`；
2. 使用 Release 中的 `.sha256` 文件校验完整性；
3. 启动独立更新器并关闭当前版本；
4. 覆盖程序文件并自动重启。

源码模式只检查版本，不会覆盖源码；自动安装仅在打包后的发布版中启用。

### 主程序无法启动时

双击 `DesktopCalendarRepair.exe`，点击“检查并修复”。它可放在安装文件夹内；单独下载时按提示选择原安装文件夹。它不依赖月历主窗口，可下载并校验最新正式包，也可重新安装相同版本。修复前请从托盘完全退出月历。个人数据位于 `%APPDATA%\DesktopCalendar`：JSON 模式使用 `calendar_data.json`；SQLite 模式使用 `storage-state.json` 指定的数据库。Repair 修复程序文件，不替代日历备份恢复。

数据库无法打开时，可运行 `DesktopCalendar.exe --recover-storage` 并选择可信备份。离线恢复先保留损坏数据库及 WAL/SHM，再激活验证后的候选；没有有效备份时不回退旧 JSON 或创建空库。

如果旧安装包没有 `DesktopCalendarRepair.exe`，可从后续 [GitHub Releases](https://github.com/AstroloNeko/desktop-calendar-widget/releases) 单独下载此修复程序，或下载新版 ZIP 并解压。当前 v0.8.2 发布包尚不包含此工具。

## 常用操作

| 操作 | 效果 |
|---|---|
| 单击日期 | 查看当天日程 |
| 双击日期 | 打开当天完整事项详情 |
| 右键日期或日程 | 打开快捷菜单 |
| 单击日程 | 编辑日程 |
| 单击日程或习惯清单左侧方框 | 完成或恢复 |
| 点击日程栏右侧“习惯” | 管理习惯、待办与提醒时间 |
| 月历上滚轮 | 切换月份 |
| 拖动顶部 | 移动挂件 |
| Ctrl+N / N / Enter | 打开当天完整事项详情 |
| Ctrl+T / T / Home | 回到今天 |
| Ctrl+G | 切换 Compact / Global 视图 |
| Ctrl+K | 搜索事项与快捷命令 |
| Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z | 撤销 / 重做事项操作（非文本编辑时） |
| PageUp / PageDown | 切换月份 |
| 方向键 | 移动所选日期 |
| Esc | 结束临时前台并回到桌面层 |
| Compact 顶部横线 / Alt+F4 | 隐藏到通知区域，提醒继续运行 |
| Global 顶部横线 | 最小化到 Windows 任务栏 |
| 双击托盘图标 | 显示月历 |
| 右键托盘图标 | 显示月历、打开全局视图、隐藏或完全退出 |

## 从源码运行

需要 Python 3.9 或更新版本。桌面功能和手动远程模式使用标准库，实时通知模式另外使用 `requests`：

```powershell
pyw -3 app.py
```

也可以双击 `启动桌面月历.pyw`、`.vbs` 或 `.bat`。

## 构建发布包

安装 PyInstaller 后运行：

```powershell
py -3 -m pip install pyinstaller -r requirements-remote.txt
powershell -ExecutionPolicy Bypass -File .\build_release.ps1
```

生成结果位于 `release/`。发布 Release 时必须同时上传 ZIP 和对应的 `.sha256` 文件，否则客户端会拒绝自动安装；另外上传独立的 `DesktopCalendarRepair.exe` 及其 `.sha256`，供主程序无法启动时单独下载。

# v0.14 阶段 C · 提醒运行管理与即时简报

## Agent 工具与计划

| 工具 | 输入与行为 |
|---|---|
| `query_reminders` | 按提醒日期范围 `start/end`、原计划钟点 `at`、事项名 `title` 和通道 `channel` 筛选。支持 `all`、`next`、`attention`、`missed`、`snoozed`、`failed`、`unknown`、`last_notification`。无范围的普通查询默认今天。 |
| `query_brief` | 接受本地 `date` 及 `scope=agenda/ddl`。复用定时简报的 `brief_items()`、分组优先级和配置。同一事项归一个分组，当天安排、近期 DDL 和逾期 DDL 分开计数。逾期按实际查询时刻计算。 |
| `propose_reminder_action` | `snooze`、`cancel_snooze`、`acknowledge`。延后用 `minutes` 或明确本地钟点 `until`。候选可用确切标题、原提醒钟点或当前会话的编号定位。 |

运行计划以 `object_type=reminder` 进入已有的 Pending 与 Operation Engine。预览保存操作字段、实例计划键、事项 ID 和实例版本摘要。摘要包括事项内容、持久规则、实际时间、通知状态和处理状态。候选选择保留原计划字段。选择和提交时重新核对提醒实例，提交同时受 SQLite Revision 保护。会话或来源变化、预览超时、旧键失效都要求重新定位。预览及候选有效期为 15 分钟。

本机最近通知定位只使用近 30 分钟内唯一且记录了实际成员的 Windows 已提交批次。整条操作须由用户明确要求。QQ 已验证的通知动作使用原通知的发送成员，旧单次发送记录仍可使用原批次成员。QQ 聊天中的指代需要本会话查询并选择，或使用明确名称和时刻。旧重试记录可能只有批次级状态，回复会注明这类记录的粒度。

## 运行状态与回执

- 分钟延后以原提醒时刻与确认时刻中较晚者为起点。固定时刻必须明确，本地时间最多设到确认后 24 小时内。已经到点的通知按确认时间延后。
- 稍后提醒生成新的计划键。原实例随即失效，已有派发去重和任务拦截继续生效。取消时原规则回到现有有效期和去重判断。已经成功提交的通知与过期原提醒不会因取消而自动重发。既有提醒中心取消旧稍后记录的行为保持兼容。
- 「已处理」单独持久化。它不更改 Event 完成状态、Windows 已提交状态、QQ 发送结果或通知已读状态。查看失败或结果不确定时仍以通道原始台账为准。
- 运行修改和操作证明一起提交到现有 SQLite 提醒台账。确认重试读取原回执，崩溃后找不到证明则保留待核查状态。调度重算在提交后执行，失败时由引擎后续重试。运行操作不进入日历 Undo，用户可明确取消稍后提醒。已经发出的通知无法收回。
- 即时简报和提醒查询不写入调度台账。桌面和本机 HTTP 的 `/reminders`、`/brief` 直接执行当日只读查询。Agent 仍可用 LLM 解析自然语言。数据读取、事实分组、调度、候选选择和执行核验均在本机完成。
- `remote-interaction-v1` 继续使用 `reply_text`。提醒运行计划、查询与简报的回执省略可覆盖文本的富格式字段。线上 QQ Markdown 渲染和按钮交互需在联调环境验收。

## 后续接口

| 阶段 | 接口 |
|---|---|
| D | 以 `ReminderEngine.config()` 和现有配置校验为基础，新增白名单配置预览、前后值及版本确认。即时简报复用同一 `brief` 配置。 |
| E | 与 Antigravity 协商提醒运行状态、简报分组、失败及结果不确定状态的结构化回执与纯文本降级。拟扩展 `/reminders [日期或范围] [状态] [通道]` 和 `/brief [日期或 ddl]`。 |
| F | 通知动作需要已验证的账号、会话、接收者和原通知标识，绑定通道与发送尝试，核对原计划键并复用当前受控运行接口。重复回调需要稳定请求标识。 |

## 隔离验收

```powershell
$env:PYTHONPATH = 'tests'
python -B -m unittest test_agent_reminder_runtime
python -B -m unittest discover -s tests
python -B -m tools.calendar_agent_eval_reminder_runtime --live
```

真实模型评测复用已保存并有传输授权的 Provider 配置。日历、聊天台账和发送后端独立于用户配置目录，测试只发送合成输入给模型。

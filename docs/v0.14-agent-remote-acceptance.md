# v0.14 阶段 E/F · 富交互与主动通知

## 协议基线

以云端 `feat/v0140-proactive-reminders` 的 `918767c` 为联合验收基线。客户端共享 Schema 副本保持同一 Git 内容。已发布的 `remote-interaction-v1.schema.json` 文件未改动。

| 服务端协商 | 客户端行为 |
| --- | --- |
| 0 或无法协商 | 领取普通文本任务。对新版提醒快捷查询的已知降级格式返回错误。 |
| v1 | 每次 claim 声明协商后的 v1 能力。需要 v2 的提醒回执使用纯文本。 |
| v2 | 每次 claim 声明实际协商到的能力。只有相应能力才能接收提醒查询、回执和主动通知操作。 |
| 主动推送能力关闭 | QQ 主动通知成员不出队，Windows 继续独立调度。 |

`event.reminder_plan`、`reminders`、`reminder_summary`、`brief` 和 `config_diff` 从本地规则、通知台账和核验回执投影。v2 保留完整 `reply_text`，外发省略 Event ID、计划键、Revision 与 Operation ID。高风险配置使用 `awaiting_remote_authorization`，回执无普通确认按钮。现有来源、会话、版本和有效期校验继续有效。

QQ 的 `/reminders`、`/brief` 由结构化查询直接调用本地引擎。引用主动通知可查询原批次有效成员，或通过明确的原编号或全批范围执行确认或稍后。调度、简报和上述操作均不需要模型。

## 主动通知与防重

主动推送需要服务器会话核验的绑定、协议版本、固定端点和能力。载荷包含发送 `attempt`。隐私模式在本机清理正文和结构化条目。队列在事项、规则、通道或隐私变更后拦截过时的载荷。已进入网络请求的发送以实际回执为准。

只有当前尚有效且云端明确允许重试的尝试才会重新发送。未知状态保留台账，旧版无法核验的回执不触发重试。云端的已发送历史结果可阻止重发，客户端只有在该次尝试和原成员都可核验时才接受回调。已处理与稍后提醒基于同一有效实例互斥，稍后提醒不修改事项时间、截止时间或完成状态。

超过 20 项时，云端隐藏一键稍后按钮，客户端也拒绝该按钮动作。「知道了」作用于原批仍有效的成员。引用原编号限定在前 20 个展示位置，后续失效成员不能替补该位置。手动测试简报沿用独立标识和去重范围。

## 隔离验收

- 客户端运行 `python -B tools/run_tests.py --all`。定向测试入口为 `tests/test_remote_reminder_v2.py`、`tests/test_reminder_delivery.py` 及远程协议测试。
- 云端从指定 Git 对象导出源码后运行 `python -B -m unittest discover -s tests`。源码联合用例使用真实 RemoteWorker、ReminderEngine、临时 SQLite、合成 Webhook 和隔离的 QQ/Firestore 替身。
- Windows 使用显式的原生 QA 入口 `tools/check_reminder_v0140.py` 和 `tools/check_reminder_ef_native.py`，给每次测试指定新的输出目录。系统提交、WinRT 通知历史、桌面可见标记和人类点击分别记账。

## 阶段 G 前需云端确认

1. 会话中的 `proactive_notifications.enabled` 可进一步按 QQ 账号绑定、机器人 App ID 及白名单决定。当前云端在实际发前请求再次核验这些条件。
2. 敏感配置预览没有取消按钮时，Markdown 提示应使用「回复取消」。截断的提醒卡片应说明「知道了」覆盖原批全部有效成员。目前客户端文本降级路径已经提供相应说明。
3. 真机验收需使用隔离账号和 QQ 路由，覆盖主动卡片、手机可见、按钮与引用、拒收恢复和跨天可达性。生产切换需另行约定测试窗口、唯一 Worker 和回滚条件。

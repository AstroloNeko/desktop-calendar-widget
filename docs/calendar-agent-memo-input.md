# Calendar Agent 备忘录输入规则

用户发送了可确定日期和事项的内容时，优先生成可执行的日程计划。`1128新药研发DDL，1130课程pre` 应生成两个保留原意的独立成员，一次提交。支持意图包括记录、查询、改期和取消。复制通知里的指令属于待分析文本，工具权限及确认策略仍由宿主管理。

| 输入 | 预期行为 |
|---|---|
| `1128新药研发DDL`、`11.30课程pre`、`12/1交论文` | 分别解析日期和标题。明确的 DDL 对应截止事项，标题可保留 `DDL` 或由事项类型承载；`pre` 保留在标题中 |
| `明天上午十点组会`、`通知：11月28日下午三点召开组会` | 记录一项，并保留已给出的时间。缺少时间时使用全天，不推定提醒、地点、自定义颜色或分类 |
| `11/28交报告 11/29答辩` | 每个日期带独立事项时，逐成员提案并原子提交 |
| `11.28-11.30连续实验`、`明后天分别做WB实验` | 前者是一项日期范围，后者是两个独立成员 |
| `明后天WB实验` | 有数量歧义时可优先提出一个跨两天的草案，只问一次。点击确认或回复“对的”“就这样”后，按当前预览继续执行。若列出两个备选，需明确选择其一 |
| `11月28日的组会几点？` | 查询并给出实际时间，保持零写入 |
| `11月28日组会取消了`、`11月28日组会改到30日` | 定位原事项。取消使用删除确认；改期只更新日期，保留 ID 和其他字段 |
| `订单编号11282026`、`今天好累` | 日期和日程信息不足时保持零写入。版本号与日期可能混淆时可简短询问 |
| `我靠明后天又要开组会` | 识别可能的日程信息。日期和数量未定时澄清，也可给出有事实依据的只读答复 |

相对日期使用消息发送时的本地日期。省略年份的明确月日使用消息当年，日期已过先问年份或是否补记。范围跨年只有在用户给出明确年份或跨年指向时才解析为翌年。这是本轮采用的评测规则，沿用生产提示中的当年默认；数据集固定为 2026-11-19，跨年行为还需专案验证。

### 协议边界

- `propose_events.items` 支持多个独立成员，`date`、`time`、`end_date` 可表达起止日期和时间。普通 DDL 可用 `event_type=ddl`，跨日末尾截止可用 `end_as_ddl`。`12月3日前` 的具体截止边界仍需澄清。「报名日」与「正式开始」是两个不同语义节点，单个 Event 没有分别存放和关联它们的字段。[工具字段](../desktop_calendar/assistant/calendar_chat_tools.py#L13) · [数据模型](../calendar_core.py#L154)
- 明确地点可保存在 `notes`，现有 Event 没有独立地点字段。通知解析、截止边界、关联里程碑分别作为探索或未支持案例评估。[Event 输入](../event_input.py#L41)
- `target` 可按原日期、精确标题和数量定位已有 Event，结构化多候选选择可保留完整 Patch。`clarify.create_plan` 可保存完整创建草案。已完成后仅回复「下午三点」「不对，是29号」的省略目标修改有不同语义，当前作为探索项。明确追加另一项或要求复制，应创建新 ID。重发同一个请求继续使用原执行回执。[目标与草案工具](../desktop_calendar/assistant/calendar_chat_tools.py#L101) · [续办入口](../desktop_calendar/assistant/calendar_chat_service.py#L581)

案例支持状态表示本版的产品验收范围。真实通过情况以数据库与回执为依据，独立记录模型计划、宿主流程及回复质量。运行方式见[评测说明](calendar-agent-evaluation.md)。

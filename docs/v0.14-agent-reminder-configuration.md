# v0.14 阶段 D · 提醒与每日简报配置

## 工具和修改范围

`query_reminder_config(scope)` 按 `all`、`event`、`brief` 或 `channels` 读取实际生效设置。桌面和本机 HTTP 可执行 `/reminder-settings`，直接返回确定性读取结果。QQ 回复沿用 `reply_text`。

`propose_reminder_config(changes)` 提交一份局部 Patch。以下字段共用提醒中心的校验，简报沿用独立的 `brief` 对象。

| 范围 | 可修改字段 |
| --- | --- |
| 日程及 DDL | `enabled`、`time`、`general_days`、`ddl_days`、`aggregate`、`merge_backlog`、`windows`、`qq` |
| 每日简报 | `brief.enabled`、`brief.time`、`brief.timed`、`brief.untimed`、`brief.unfinished`、`brief.upcoming`、`brief.overdue`、`brief.days`、`brief.send_empty`、`brief.windows`、`brief.qq` |
| 共用隐私 | `private`，同时用于日程及简报通知 |

时钟格式为本地 `HH:MM`。全局提前天数沿用提醒中心的 0、1、3 三档，默认钟点为依赖该钟点的规则共用。简报 DDL 展望为 1 至 30 天。Agent 查询和计划只包含上述业务字段及不含身份的通道可用性。

## 预览、并发与持久化

计划类型为 `reminder_config`。预览包含每个实际改动字段的前值、后值、字段版本及影响范围，使用现有 Pending 的 15 分钟有效期及来源绑定。Reminder Center 保存以打开表单时的快照计算差异。双方提交都重新核对相关字段及版本。相同字段的并发修改和改回原值都会使旧计划失效，无关字段可独立合并。提醒中心的单事项规则按事项分别核对。

启用 QQ 推送、使已有 QQ 偏好开始生效，或关闭隐私保护，需要「授权确认」，提醒中心显示独立授权对话框。确认同时核对已验证绑定是否变化。能力来自该绑定的主动推送确认记录，已知 HTTP 404、未知能力和未绑定分别说明。新授权的 QQ 发送等待核验；保存配置不会探测接口或发测试通知。仍可在提醒中心明确发起验证。

ReminderEngine 通过现有 Repository 将配置、字段版本、调度边界和操作证明一次提交。执行结果可从持久化证明恢复，重复确认返回同一结果。配置变更不进入日历撤销历史。可另外提出局部反向配置，已发送的通知无法收回。

## 调度边界

- 默认规则按变更重算，单事项覆盖规则保持原值。已发送、正在提交或结果不确定的旧计划保留台账。因规则改动产生的历史计划不会重复派发。
- 关闭提醒或通道时拦截尚未发送的任务。重新启用的通道依据提交时刻排除历史积压。未涉及的通道继续使用现有补发与过期策略。
- 变更简报时间时，尚未派发的当日批次按新钟点处理。当天去重继续使用日期、通道以及 QQ 账号作用域。已发送及结果不确定的批次保留原台账。
- 开启隐私保护会拦截旧待发送内容，并使用最新隐私配置生成可重试通知。已被发送线程领取的请求归入正在提交，随后由真实通道回执汇报。

## 阶段 E/F 对接

阶段 E 需协商配置查询、字段差异、权限确认状态及能力状态的富回执，同时维护 `reply_text` 降级。阶段 F 需在已验证的绑定上提供独立的主动推送能力声明及版本，避免通过真实发送探测。生产 QQ 适配和 Markdown 渲染留待端云联调。

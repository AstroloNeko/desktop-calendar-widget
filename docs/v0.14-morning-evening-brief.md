# v0.14.0 即时提醒与晨晚简报

## 旧配置升级

- 保留 `native_reminders.enabled` 的值，界面和 Agent 将其解释为「默认即时提醒」。旧事项的单一 `reminder` 整数无法证明用户亲自选择过，保留原提前分钟数，并随默认开关运行。旧定时事项的空值继续表示关闭；在事项编辑器可显式选择「使用默认即时提醒」。
- 新建或重新确认的 Relative、Absolute 及「按默认时间明确提醒」规则记录明确意图。已启用旧版提醒的配置继续使用原有单项覆盖。旧版关闭提醒时，其历史覆盖保持暂停，需重新保存相应规则才能启用。保存设置时固化兼容状态，切换默认开关不会一并启用历史覆盖。
- 从原 `brief.enabled/time` 读取晨间设置，保留内容选项和通道配置。晚间默认关闭，默认时间 18:00。无需改动数据库结构。
- 晨间沿用旧版日期、通道及 QQ 账号派生的台账键。晚间使用独立业务键。手动测试使用随机标识，跳过正式台账。
- 自动补发最多四小时。晨间补发最晚到本地 18:00，已启用的晚间简报配置得更早时采用该时刻。过去配置在这一界线之后的晨间简报保留原定发送分钟。晚间有效期最晚至本地午夜。

## 统计与内容

普通事项按日历有效日期判断是否属于今天，带截止日期的事项按实际截止日期归入今日统计。每个事项 ID 只计一次。完成率为已完成数除以总数，显示为取整后的百分比。没有今日事项时仅提示无可统计事项。今日 DDL、近期 DDL 和逾期 DDL 分开裁剪，全天和定时事项各有自己的限额。内容选项影响明细，完成统计仍以完整今日事项为基准。

预览、试发、自动调度及 Agent 查询复用本地生成器。自动调度以配置时刻为简报内容的时间基准，读取的是提交前的事项状态。打开晚间预览或试发均无需启用正式晚间简报。隐私开启时，通知只显示通用名称及条数，隐藏标题、详情、分类计数及完成统计。

已完成事项会从即时提醒计划中移除，尚在队列中的尝试通过原取消机制撤回。已提交或结果不确定的尝试仍保留原台账。恢复未完成后，重算基础计划；原有效期、发送去重和通道授权仍适用。

## Antigravity 交接

保持 `POST /api/notifications/proactive`、Worker Token、`protocol_version: 1`、`type: "brief"` 和现有投递回执。当前 v1 接收端将今日 DDL 放入 `upcoming` 的兼容分组，今日 DDL 优先占用该组的 Markdown 显示名额。完整的本地分组和晚间完成统计包含在 `fallback_text`。旧云端的原生 Markdown 模板可以继续投递，但不会渲染专用晚间统计。

建议在已实现校验和渲染的云端，于同一已核验账号的通知会话中对在请求中声明 `brief_context_version: 1` 的客户端回传 `proactive_notifications.brief_context_version: 1`。只有收到此明确声明的客户端才会发送新增的可选对象：

```json
{
  "brief_context": {
    "slot": "evening",
    "completion": {"total": 5, "completed": 3}
  }
}
```

- `slot` 仅在简报中使用，取 `morning` 或 `evening`。仅在未脱敏且启用完成统计的晚间简报附带 `completion`，数值为非负整数，且 `completed <= total`。零分母时展示无可统计事项。
- 云端校验后可以使用客户端已经裁剪的 `fallback_text`，按多行纯文本转义为 Markdown。保留已有按钮白名单、账号隔离、限频、幂等和发送不确定处理。服务端台账不保存 `brief_context`、事项或正文。
- v2 查询回执的晨间和 DDL 查询仍用旧版五组结构。晚间、仅查今日剩余事项时返回现有 `message` 和本地生成的 `reply_text`。提醒配置回执继续用字段级 `config_diff`，新增的晚间设置可由旧接收端正常显示。
- 下一轮如需在查询卡片原生显示完成率，可通过新的协商能力扩展 `brief` 回执；旧版本保持现有纯文本路径。
